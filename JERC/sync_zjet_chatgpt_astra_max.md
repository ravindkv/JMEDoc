# Z+jet residual JEC synchronization audit: JERCSW vs NanoAnalysis

Audit date: 2026-09-07. Scope: **ZmmJet and ZeeJet, 2016Pre, 2016Post, 2017 and 2018**, using the local AK4CHS/NanoAODv9 Run 2 code. JERCSW's L3 absolute-response path is the closest counterpart to NanoAnalysis's ZbAnalysis response histograms; JERCSW's L2 path is covered separately wherever it differs.

**The two checked-out chains are not synchronized.** The longitudinal response algebra largely agrees, but samples, selection, correction state, MET inputs, recoil jets and weights differ. There are also concrete implementation and integration problems that must be resolved before a production-to-production comparison is meaningful. This report records observed code behavior, not a claim that either framework has been run successfully on the same events. It does not assume that either framework is the reference physics prescription.

“NanoAnalysis” below means the Coffea ZbAnalysis implementation and the functions it calls. Several of its current shared helpers instead dispatch to RDF interfaces; where that prevents execution, the report explicitly labels the underlying Coffea physics definition as intended/conditional. Zee is particularly incomplete. A commented alternative, unused helper, similarly named config, or legacy fit file is not counted as active behavior.

## What already agrees

- The configured inclusive NLO DY **DAS dataset path** is identical in both frameworks in all four periods. This does not establish equality of the processed file lists.
- The final Zmm HLT path agrees per year when the necessary branch is retained.
- The union of the configured Nano certification masks equals the JERCSW Run 2 golden masks exactly; the 2016 APV/post masks do not overlap.
- The four corresponding Rochester UL text payloads are byte-identical. Their selection, matching and random-number prescriptions differ.
- Both use pT(Z)>=15 GeV, and L3's back-to-back requirement agrees apart from the exact boundary.
- With identical transverse inputs, longitudinal DB, MPF, MPF1, MPFn and MPFu have the same algebra. Formula checks do not establish equality of the actual inputs or selected histograms.

### JER implementation differences requiring attention

Write sigma for relative resolution and S for its scale factor. JERCSW uses a matched hybrid factor `1+(S-1)*(pTcorr-pTgen)/pTcorr` if genJetIdx is valid, ΔR<0.2, and abs(pTcorr-pTgen)<3*sigma*pTcorr; otherwise it uses `1+sigma*sqrt(max(S*S-1,0))*N(0,1)`. The normal deviate is hash-deterministic from pT,eta,rho,eventID (eventID hashed from run,lumi,event). The exact formulas are in bundled [jer_smear.json.gz](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/POG/JME/jer_smear.json.gz); matching/seeding is [ScaleJetFunction.cpp:258](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/ScaleJetFunction.cpp:258). The resolution is evaluated using `skimT.Jet_pt` **before corrected jets are written back**, i.e. Nano input pT, whereas gen matching and smear reference use new JEC-corrected pT ([ScaleJetFunction.cpp:170](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/ScaleJetFunction.cpp:170), [ScaleJetFunction.cpp:269](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/ScaleJetFunction.cpp:269); [ScaleJet.cpp:165](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/ScaleJet.cpp:165); [RunL3ResidualZllJet.cpp:182](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/RunL3ResidualZllJet.cpp:182)). This mixed pT convention should be synchronized deliberately. If JER evaluation throws or returns a nonfinite/nonpositive factor, JERCSW substitutes **1**, which is also different from Nano's unguarded multiplier ([ScaleJetFunction.cpp:362](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/ScaleJetFunction.cpp:362)).

Nano's active separate smearing function instead returns **`Normal(1,sigma(rawPt))*sqrt(max(S*S-1,0))`**, not `1+Normal(0,sigma)*sqrt(...)`. This is a substantive formula error: S=1 produces factor 0, and for S>1 its mean is sqrt(S²-1), not 1. It has no gen matching, no explicit positivity clamp and uses unseeded global numpy randomness. It is applied to both full-JEC pT/mass and **L1RC pT/mass**, unlike JERCSW's unsmeared L1 baseline ([JetCorrections.py:415](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/Framework/src/nanoanalysis/JetCorrections.py:415), [JetCorrections.py:467](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/Framework/src/nanoanalysis/JetCorrections.py:467)). The factory JEC stack is built from JEC entries alone ([JetCorrections.py:285](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/Framework/src/nanoanalysis/JetCorrections.py:285)); separate reso/resosf objects are created at [JetCorrections.py:352](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/Framework/src/nanoanalysis/JetCorrections.py:352).

### Response formula mapping

Use transverse vectors `q = vector pT(Z)`, `j = vector pT(jet1)`, `n = vector sum(other jets)`, `m = corrected MET`, `u = -(m+q+j+n)`, `Q = magnitude(q)` and `J = magnitude(j)`. These formulae are transcribed/algebraically reduced from code, not assumed from observable names.

| Observable | Formula | Comparison |
|---|---|---|
| DB / balance | J/Q | Same JERCSW L3 `respDb` and Nano `db`. |
| MPF | 1+m·q/Q² | Same JERCSW L3 `respMpf` and Nano `mpf`. |
| MPF1 | −j·q/Q² = −DB cos(Δphi) | Same: JERCSW writes `1−(q+j)·q/Q²`, Nano writes `−j·q/Q²`. This is **projected balance**, and differs from DB away from exactly back-to-back. |
| MPFn | −n·q/Q² | Same algebra; requires an identical definition of n. |
| MPFu | −u·q/Q² | Same algebra; requires identical MET, Z and recoil jets. |
| MPFnu | MPFn+1.1 MPFu | Extra JERCSW L3 observable; no direct Nano counterpart in ZbHistograms. |

Evidence: [MathL3Residual.cpp:75](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/MathL3Residual.cpp:75), [MathHdm.cpp:75](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/MathHdm.cpp:75); [ZbHistograms.py:276](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/ZbAnalysis/ZbHistograms.py:276). Both longitudinal implementations obey MPF=MPF1+MPFn+MPFu. JERCSW explicitly checks closure at [MathHdm.cpp:165](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/MathHdm.cpp:165). Thus a different leading/other jet split can move MPFn and MPFu oppositely without changing total MPF. `mpfnotypeI` in Nano is a FIXME alias of type-I MPF, not an independent uncorrected-MET response ([ZbHistograms.py:307](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/ZbAnalysis/ZbHistograms.py:307)); booking/filling is commented out ([ZbHistograms.py:124](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/ZbAnalysis/ZbHistograms.py:124), [ZbHistograms.py:325](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/ZbAnalysis/ZbHistograms.py:325)).

Recoil collection differs: JERCSW sums jets with pT>=12 and both channel-specific lepton indices −1; its second sum loop **does not repeat ΔR cleaning** used in candidate ranking, so an index-free jet rejected by ΔR can re-enter the recoil ([PickZllJet.cpp:402](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/PickZllJet.cpp:402), [PickZllJet.cpp:458](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/PickZllJet.cpp:458)). Nano sums all retained `events.Jet`, without imposing the pT>12 or eta<5 subset used to define leadingJet ([ZbHistograms.py:270](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/ZbAnalysis/ZbHistograms.py:270); [analysis.py:189](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/ZbAnalysis/analysis.py:189)). Consequently its alpha jet (`events.Jet[:,1]`) need not be the second jet of the leadingJet candidate subset. Nano's cleaning removes ΔR<0.3 jets relative to selected muons, whereas JERCSW uses ΔR<0.4 for candidate selection (object section covers full details).

Perpendicular components are **not the same convention**. With q_perp=Rot(+pi/2)q, JERCSW MathHdm `mpfx=1+m·q_perp/Q²`, while Nano rotates **m**, giving `mpfx=1−m·q_perp/Q²`: the values sum to 2. JERCSW MathHdm `mpf1x=1−j·q_perp/Q²`, Nano `mpf1x=+j·q_perp/Q²`: the values sum to 1. Evidence: [MathHdm.cpp:134](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/MathHdm.cpp:134), Nano [ZbHistograms.py:303](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/NanoAnalysis/NanoAODAnalysis/ZbAnalysis/ZbHistograms.py:303). **Activation caveat:** JERCSW's present L3 wrapper only copies longitudinal fields ([MathL3Residual.cpp:75](/Users/ravindrakumar/rverma/JME/JMEDoc/JERC/Sync/JERCSW/Hist/cpp/MathL3Residual.cpp:75)), so these MathHdm perpendicular definitions are not actually booked as L3 output by `HistL3Residual`.

### L2-specific math: cannot substitute L3 MPF by name
